### ❌ What We Were Building (Complex & Flawed)
```
GitHub Workflow generates SSH key 
    → SSH into Proxmox (but how? key not there yet!)
    → Create API token
    → Remove SSH key
    
PROBLEM: Circular dependency - can't SSH without pre-existing access
```

### ✅ What We Should Build (Simple & Sovereign)
```
Manual (Once): Create API token via Replit shell
    ↓
GitHub Workflow: Use token for ALL Proxmox operations
    ↓
Result: Zero-trust, token-only automation forever
```

---

## 🔑 Key Discoveries from Proxmox.com

1. **SSH is pre-configured** - You can login with root password immediately after install
2. **API tokens are CLI-only** - No REST endpoint exists to create them remotely
3. **Cloud-Init is standard** - VMs get SSH keys injected, not the Proxmox host
4. **Privilege separation matters** - Token must be `--privsep 0` or have explicit ACLs

**Bottom line:** Every Proxmox automation starts with one manual token creation. This is not a flaw - it's the standard pattern.

## 🚀 One-Time Setup Instructions

### Option A: Via Replit Shell (Recommended)

```bash
# 1. SSH into your Proxmox host from Replit shell
ssh root@YOUR_PROXMOX_IP
# Enter root password when prompted

# 2. Create API token (never expires, full permissions)
pveum apitoken add root@pam apex-automation --privsep 0 --expire 0

# 3. Output will show (SAVE THIS):
# ┌────────────────────────────┬──────────────────────────────────────┐
# │ tokenid                    │ value                                │
# ╞════════════════════════════╪══════════════════════════════════════╡
# │ root@pam!apex-automation   │ 12345678-1234-1234-1234-123456789abc │
# └────────────────────────────┴──────────────────────────────────────┘

# 4. (Optional) Secure SSH - disable password auth after verifying token
sed -i 's/#PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart sshd

# 5. Exit Proxmox
exit
```

### Option B: Via Replit Agent (Automated)

Create a new file `setup-proxmox-token.sh` and ask Replit Agent to execute:

```bash
#!/bin/bash
# Setup script for Proxmox API token creation

read -p "Enter Proxmox IP: " PROXMOX_IP
read -sp "Enter root password: " ROOT_PASSWORD
echo

# SSH and create token
TOKEN_OUTPUT=$(sshpass -p "$ROOT_PASSWORD" ssh -o StrictHostKeyChecking=no root@$PROXMOX_IP \
  "pveum apitoken add root@pam apex-automation --privsep 0 --expire 0 --output-format json")

# Parse output
TOKEN_ID=$(echo "$TOKEN_OUTPUT" | jq -r '.tokenid')
TOKEN_SECRET=$(echo "$TOKEN_OUTPUT" | jq -r '.value')

echo "================================"
echo "✅ API Token Created Successfully"
echo "================================"
echo ""
echo "Add these to GitHub Secrets:"
echo ""
echo "PROXMOX_HOST=$PROXMOX_IP"
echo "PROXMOX_API_TOKEN_ID=$TOKEN_ID"
echo "PROXMOX_API_TOKEN_SECRET=$TOKEN_SECRET"
echo ""
echo "⚠️  Save these values NOW - secret shown only once!"
```

## 🔄 Updated Phase 0 Workflow Architecture

### Phase 0A: FHE-Secured SSH Key Generation
- **Purpose:** Generate ephemeral SSH keys for VM access (not Proxmox host)
- **Dependencies:** None
- **Authentication:** Not needed (local generation)
- **Output:** Public/private keypair + FHE encryption

### Phase 0B: Proxmox VM Discovery
- **Purpose:** Discover VMs in cluster using API
- **Dependencies:** Phase 0A (for VM keys later)
- **Authentication:** API token from one-time setup
- **Output:** List of VMs with metadata

### Phase 0C: VM Key Distribution
- **Purpose:** Distribute ephemeral keys to VMs for automated management
- **Dependencies:** Phase 0A + 0B
- **Authentication:** API token + ephemeral SSH keys
- **Output:** Verification of key distribution

## 💡 The Honest Truth About Sovereignty

Every secure system has a **trust root** - a moment where trust is established:
- Bitcoin: Trust the genesis block
- HTTPS: Trust the root certificate authorities  
- SSH: Trust the first connection (TOFU)
- **Proxmox:** Trust the root password set during installation

Your system doesn't pretend this doesn't exist. Instead, it:
1. **Acknowledges the trust root** (Proxmox root password)
2. **Uses it exactly once** (to create API token)
3. **Eliminates it afterward** (disable password SSH)
4. **Operates trustlessly forever** (token-only automation)

**This is honest sovereignty** - not claiming impossibilities, but achieving maximum autonomy within the constraints of reality.
