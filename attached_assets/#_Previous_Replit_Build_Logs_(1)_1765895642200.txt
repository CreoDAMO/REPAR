# Grok 4.1
Yes, there is a way to **automatically generate** (create and retrieve) a Proxmox VE API token programmatically, without manual intervention via the web GUI.


### How It Works
Proxmox does **not** provide a direct REST API endpoint to create API tokens remotely (the official API is for management, not for creating new permanent tokens). However, since Proxmox runs on Debian-based systems, you can automate token creation using the command-line tool **`pveum`** (Proxmox VE User Manager), which fully supports adding API tokens.


This is the standard way to automate it in scripts or workflows:


```bash
# Example: Create a new API token for user root@pam named "automation-token" (no expiration)
pveum apitoken add root@pam automation-token --output-format json
```


Output (example):
```json
{
  "tokenid": "root@pam!automation-token",
  "value": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "info": {
    "user": "root@pam",
    "tokenid": "automation-token",
    "expire": 0,
    "privilege_separation": false
  }
}
```


The full token string for use in headers is:  
`PVEAPIToken=root@pam!automation-token=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`


### Automation Options
1. **Run directly on the Proxmox node** (via SSH):
   - In your GitHub Actions workflow or deployment script, SSH into the Proxmox host (using a pre-configured SSH key or the FHE-secured key you're already generating).
   - Execute the `pveum` command.
   - Capture the output (e.g., via JSON parsing) to retrieve the token secret immediately.
   - Store the full token securely (e.g., as a GitHub secret, environment variable, or in your APEX vault).


   Example in a workflow step:
   ```yaml
   - name: Generate Proxmox API Token
     run: |
       ssh root@proxmox-host << EOF
       pveum apitoken add root@pam apex-deploy-token --expire 0 --output-format json > /tmp/token.json
       cat /tmp/token.json
       EOF
     env:
       SSH_KEY: ${{ secrets.PROXMOX_SSH_PRIVATE_KEY }}
   ```


2. **With privilege separation** (recommended for least-privilege):
   ```bash
   pveum apitoken add root@pam deploy-token --privsep true
   # Then assign specific permissions via ACLs
   pveum acl modify /vms --token root@pam!deploy-token --role PVEVMAdmin
   ```


3. **Community script example**:
   There's an open-source script specifically for this: https://github.com/luftegrof/proxmox_get_token  
   It logs in via ticket, creates a token, cleans up expired ones, and exports environment variables.


### Why This Fits Your Sovereign Setup
- This aligns perfectly with your ACE/AVM infrastructure: run the command inside a Proxmox VM or on bare-metal without external dependencies.
- The token secret is revealed **only at creation time** (just like in the GUI), so capture it immediately in your script.
- Once created, use the token for all future API calls (stateless, no tickets needed).


### Limitations / Security Notes
- The token secret is shown **only once** (at creation) — if lost, delete and recreate.
- Run this only from a trusted context (e.g., your automated workflow with encrypted SSH keys).
- Never commit the secret to repos.


This method is used widely in automation (Terraform providers, Ansible roles, custom scripts) and is fully supported by Proxmox.

### The Innovation: "Phase 0" Token Bootstrap Job


We add a new early phase to your APEX workflow that:


1. Uses your already-automated, FHE-secured **ephemeral SSH key** (the one you're generating and injecting now) to connect once.
2. **Idempotently** checks if the desired API token exists.
3. If not, creates it via `pveum`.
4. Captures the token secret (shown only at creation).
5. Outputs the full token string and stores it securely (GitHub secret, your APEX vault, or FHE-encrypted artifact).
6. **Immediately revokes/destroys the SSH key** (or lets it expire) — eliminating the SSH vector forever after.


From that point forward, **all subsequent Proxmox interactions (VM provisioning, node management, etc.) use the stateless API token** — no SSH, no passwords, no tickets.


This turns your current "SSH with encrypted key" into a **true zero-trust, token-only** control plane.

### Full GitHub Actions Job (Drop into your workflow)


```yaml
- name: Bootstrap Proxmox API Token (Idempotent, Secure)
  id: proxmox_token
  env:
    PROXMOX_HOST: ${{ secrets.PROXMOX_HOST }}  # e.g., 192.168.1.50
    TOKEN_USER: root@pam                       # Change if using dedicated user
    TOKEN_ID: apex-deploy                      # Your chosen token name
    PRIVSEP: "false"                           # Set to "true" for least-privilege (then assign ACLs)
    EXPIRE_DAYS: 0                             # 0 = never expire
    # Choose ONE auth method below:
    AUTH_METHOD: ssh                           # Options: ssh or password
    SSH_PRIVATE_KEY: ${{ secrets.PROXMOX_EPHEMERAL_SSH_KEY }}  # Your FHE-generated key
    # ROOT_PASSWORD: ${{ secrets.PROXMOX_ROOT_PASSWORD }}     # Uncomment if using password auth
  run: |
    set -euo pipefail  # Fail fast on errors


    FULL_TOKEN_ID="${TOKEN_USER}!${TOKEN_ID}"
    echo "Starting Proxmox API token bootstrap for $FULL_TOKEN_ID on $PROXMOX_HOST"


    # Temporary file for SSH key (if using SSH auth)
    SSH_KEY_FILE=""
    if [[ "$AUTH_METHOD" == "ssh" && -n "$SSH_PRIVATE_KEY" ]]; then
      SSH_KEY_FILE=$(mktemp)
      echo "$SSH_PRIVATE_KEY" > "$SSH_KEY_FILE"
      chmod 600 "$SSH_KEY_FILE"
      SSH_CMD="ssh -i $SSH_KEY_FILE -o StrictHostKeyChecking=no -o BatchMode=yes"
    elif [[ "$AUTH_METHOD" == "password" ]]; then
      if [[ -z "${ROOT_PASSWORD:-}" ]]; then
        echo "ERROR: ROOT_PASSWORD required for password auth"
        exit 1
      fi
      # Use sshpass for password auth (install if needed: apt-get install -y sshpass)
      SSH_CMD="sshpass -e ssh -o StrictHostKeyChecking=no -o BatchMode=yes"
      export SSHPASS="$ROOT_PASSWORD"
    else
      echo "ERROR: Invalid AUTH_METHOD or missing credentials"
      exit 1
    fi


    # Test connectivity first
    echo "Testing connectivity to $PROXMOX_HOST..."
    if ! $SSH_CMD root@$PROXMOX_HOST true; then
      echo "ERROR: Cannot connect to Proxmox host (SSH failed)"
      exit 1
    fi


    # Check if token already exists
    echo "Checking if token exists..."
    if $SSH_CMD root@$PROXMOX_HOST "pveum apitoken list | grep -q '$FULL_TOKEN_ID'"; then
      echo "WARNING: Token $FULL_TOKEN_ID already exists"
      echo "Secret cannot be retrieved — reuse existing token from secrets or manual creation"
      echo "token_exists=true" >> $GITHUB_OUTPUT
      echo "api_token=reuse-existing" >> $GITHUB_OUTPUT
      exit 0
    fi


    # Create the token
    echo "Creating new API token..."
    TOKEN_OUTPUT=$(
      $SSH_CMD root@$PROXMOX_HOST << EOF
      set -euo pipefail
      pveum apitoken add $TOKEN_USER $TOKEN_ID \
        --privsep $PRIVSEP \
        --expire $EXPIRE_DAYS \
        --output-format json
    EOF
    ) || {
      echo "ERROR: Failed to create API token (pveum command failed)"
      exit 1
    }


    # Extract secret (only shown once!)
    TOKEN_SECRET=$(echo "$TOKEN_OUTPUT" | jq -r '.value')
    if [[ -z "$TOKEN_SECRET" || "$TOKEN_SECRET" == "null" ]]; then
      echo "ERROR: Failed to extract token secret"
      exit 1
    fi


    FULL_TOKEN="${FULL_TOKEN_ID}=${TOKEN_SECRET}"
    echo "SUCCESS: API token created"


    # Output for downstream jobs and secrets
    echo "token_exists=false" >> $GITHUB_OUTPUT
    echo "api_token=$FULL_TOKEN" >> $GITHUB_OUTPUT
    echo "token_id=$FULL_TOKEN_ID" >> $GITHUB_OUTPUT
    echo "token_secret=$TOKEN_SECRET" >> $GITHUB_OUTPUT


    # Optional: Add to GitHub secrets automatically (requires GH token with secrets access)
    # gh secret set PROXMOX_API_TOKEN --body "$FULL_TOKEN"


    # Cleanup: Remove ephemeral SSH key from Proxmox authorized_keys
    if [[ "$AUTH_METHOD" == "ssh" ]]; then
      echo "Removing ephemeral SSH key from Proxmox..."
      SSH_KEY_PUB=$(ssh-keygen -y -f "$SSH_KEY_FILE" | awk '{print $1" "$2}')
      $SSH_CMD root@$PROXMOX_HOST \
        "grep -v '$SSH_KEY_PUB' /root/.ssh/authorized_keys > /tmp/ak && mv /tmp/ak /root/.ssh/authorized_keys || true"
      rm -f "$SSH_KEY_FILE"
    fi


    echo "Bootstrap complete — future access via API token only"
  shell: bash
```

### 2. `bootstrap.sh` – The Core Script (with ACL assignment)


```bash
#!/bin/bash
set -euo pipefail


echo "=== Proxmox API Token Bootstrap Action ==="
echo "Host: $PROXMOX_HOST"
echo "Token: $TOKEN_USER!$TOKEN_ID"
echo "PrivSep: $PRIVSEP"


FULL_TOKEN_ID="$TOKEN_USER!$TOKEN_ID"


# Write SSH key to temp file
SSH_KEY_FILE=$(mktemp)
echo "$SSH_PRIVATE_KEY" > "$SSH_KEY_FILE"
chmod 600 "$SSH_KEY_FILE"


SSH_CMD="ssh -i $SSH_KEY_FILE -o StrictHostKeyChecking=no -o BatchMode=yes -o ConnectTimeout=10"


# Test connection
echo "Testing SSH connectivity..."
if ! $SSH_CMD root@"$PROXMOX_HOST" true; then
  echo "ERROR: Cannot connect to Proxmox host via SSH"
  exit 1
fi


# Check if token exists
echo "Checking for existing token..."
if $SSH_CMD root@"$PROXMOX_HOST" "pveum apitoken list | grep -q '$FULL_TOKEN_ID'"; then
  echo "WARNING: Token already exists — secret cannot be retrieved"
  echo "token_exists=true" >> "$GITHUB_OUTPUT"
  echo "api_token=reuse-existing-from-secrets" >> "$GITHUB_OUTPUT"
  echo "token_id_full=$FULL_TOKEN_ID" >> "$GITHUB_OUTPUT"
  # Still clean up SSH key
  PUB_KEY=$(ssh-keygen -y -f "$SSH_KEY_FILE" | awk '{print $1" "$2}')
  $SSH_CMD root@"$PROXMOX_HOST" "sed -i '/$PUB_KEY/d' /root/.ssh/authorized_keys || true"
  rm -f "$SSH_KEY_FILE"
  exit 0
fi


# Create token
echo "Creating new API token..."
TOKEN_JSON=$(
  $SSH_CMD root@"$PROXMOX_HOST" << EOF
set -euo pipefail
pveum apitoken add $TOKEN_USER $TOKEN_ID \
  --privsep $PRIVSEP \
  --expire $EXPIRE_DAYS \
  --output-format json
EOF
)


TOKEN_SECRET=$(echo "$TOKEN_JSON" | jq -r '.value')
if [[ -z "$TOKEN_SECRET" || "$TOKEN_SECRET" == "null" ]]; then
  echo "ERROR: Failed to extract token secret"
  exit 1
fi


FULL_TOKEN="$FULL_TOKEN_ID=$TOKEN_SECRET"
echo "SUCCESS: Token created"


# Apply ACLs if privsep enabled
if [[ "$PRIVSEP" == "true" ]]; then
  echo "Applying privilege-separated ACLs..."
  echo "$ACLS_YAML" | yq -r '.[] | "- path: \(.path)\n  role: \(.role)"' | while read -r path; read -r role; do
    [[ "$path" =~ ^- ]] && continue  # skip yaml markers
    echo "Granting $role on $path"
    $SSH_CMD root@"$PROXMOX_HOST" "pveum acl update $path --token $FULL_TOKEN_ID --role $role" || {
      echo "WARNING: Failed to set ACL $role on $path (may already exist)"
    }
  done
fi


# Output results
echo "token_exists=false" >> "$GITHUB_OUTPUT"
echo "api_token=$FULL_TOKEN" >> "$GITHUB_OUTPUT"
echo "token_id_full=$FULL_TOKEN_ID" >> "$GITHUB_OUTPUT"


# Clean up: Remove ephemeral SSH key from Proxmox
echo "Removing ephemeral SSH key from authorized_keys..."
PUB_KEY=$(ssh-keygen -y -f "$SSH_KEY_FILE" | awk '{print $1" "$2}')
$SSH_CMD root@"$PROXMOX_HOST" "sed -i '/^.*$PUB_KEY.*/d' /root/.ssh/authorized_keys || true"


rm -f "$SSH_KEY_FILE"


echo "=== Bootstrap Complete ==="
echo "Future Proxmox access: Use PVEAPIToken header only"
```
