## Key Finding #2: **Cloud-Init is the Standard Automation Path** 🚀

Cloud-Init is the de facto multi-distribution package that handles early initialization, including configuration of network devices and SSH keys [Proxmox VE](https://pve.proxmox.com/wiki/Cloud-Init_Support) .

**Critical realization:** You're solving the **wrong bootstrap problem**.

Your current approach bootstraps **the Proxmox host itself** every time, but you should be bootstrapping **VMs** after the host is set up once.

## Key Finding #3: **API Token Creation is CLI-Only** 🔐

From official docs: API tokens allow stateless access to most parts of the REST API. To use an API token, set the HTTP Authorization header to PVEAPIToken=USER@REALM!TOKENID=UUID [Proxmox VE](https://pve.proxmox.com/wiki/Proxmox_VE_API)

**Critical point:** Tokens can ONLY be created via:
- `pveum apitoken add` command (requires SSH or console)
- Web UI (requires manual interaction)

There is **NO REST API endpoint** to create tokens remotely. Grok 4.1 was correct about this limitation.

## Key Finding #4: **Privilege Separation Matters** ⚠️

From forum discussions: With privilege separation enabled, tokens return data:null as a response until ACLs are explicitly configured [Proxmox](https://forum.proxmox.com/threads/api-token-config.92465/) .

**This explains potential failures in Grok's approach** - you can't just create a token and expect it to work. You must:
1. Create token with `--privsep false` (inherits user permissions), OR
2. Create token with `--privsep true` + explicitly assign ACLs
