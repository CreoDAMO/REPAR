#### NEW APPROACH: Use ACE Native Deployment

Instead of SSH, the workflow should:

1. **Call ACE Workload API** to deploy services
2. **Use ACE's built-in scheduler** for optimal placement
3. **Leverage ACE's IPFS integration** for artifact distribution
4. **Monitor via ACE's Prometheus metrics**

**Implementation Pattern:**
```yaml
deploy-service-to-ace:
  runs-on: ubuntu-latest
  steps:
    - name: Download artifact
      uses: actions/download-artifact@v4
      with:
        name: ${{ SERVICE_NAME }}-dist
    
    - name: Deploy to ACE
      run: |
        # Use ACE's native deployment API (not SSH)
        ACE_ENDPOINT="${{ needs.deploy-vm-infrastructure.outputs.ace_endpoint }}"
        
        # Upload artifact to ACE
        curl -X POST "$ACE_ENDPOINT/api/v1/workload/deploy" \
          -H "Authorization: Bearer ${{ secrets.ACE_TOKEN }}" \
          -F "artifact=@${{ SERVICE_NAME }}-dist.tar.gz" \
          -F "service=${{ SERVICE_NAME }}" \
          -F "replicas=3" \
          -F "network=constellation"
        
        # Verify deployment
        curl "$ACE_ENDPOINT/api/v1/workload/${{ SERVICE_NAME }}/status"
```

**This aligns with how ACE was designed to work.**
