## 🔐 Answering Your Question: SSH Key Retrieval

> "Can I now retrieve the SSH private key password to store in GitHub Actions Secrets Manager?"

### **Short Answer: Sort of, but there's a better way**

Here's what's happening:

### Current Flow (Phase 0):
```python
# Generate ephemeral SSH key
ssh-keygen -t ed25519 -f ./ephemeral_key -N ""

# Encrypt it with FHE
encrypted_key = orchestrator.encrypt_with_bootstrap(private_key_b64.encode())

# Output for next jobs
echo "EPHEMERAL_KEY=$PRIVATE_KEY" >> $GITHUB_OUTPUT
::add-mask::$PRIVATE_KEY  # Masks it in logs
```

### The Problem:
The `EPHEMERAL_KEY` output is **scoped to the `automate-ssh-keys` job only**. GitHub Actions doesn't automatically pass job outputs to other jobs unless you explicitly:

1. **Define it in the job's `outputs:`** section
2. **Reference it via `needs.automate-ssh-keys.outputs.EPHEMERAL_KEY`**

## 🔧 Two Solutions

### Option A: Fix the Workflow (Recommended - No Manual Intervention)

**Update `automate-ssh-keys` job:**

```yaml
automate-ssh-keys:
  name: Automate SSH Key Generation (FHE-Secured)
  runs-on: ubuntu-latest
  outputs:
    ephemeral_key: ${{ steps.encrypt.outputs.ephemeral_key }}  # ← ADD THIS
    public_key: ${{ steps.distribute.outputs.public_key }}
  
  steps:
    # ... (keep existing steps)
    
    - name: FHE-Secure Private Key
      id: encrypt  # ← ADD ID
      env:
        PRIVATE_KEY: ${{ steps.generate.outputs.private_key }}
      run: |
        # ... (existing FHE encryption)
        
        # Output the encrypted key for other jobs
        echo "ephemeral_key=$PRIVATE_KEY" >> $GITHUB_OUTPUT  # ← KEY CHANGE
        echo "::add-mask::$PRIVATE_KEY"
```

**Update `deploy-founder-node` job:**

```yaml
deploy-founder-node:
  name: Deploy Founder Node
  runs-on: ubuntu-latest
  needs: [build-aequitasd, validate-apex, automate-ssh-keys]  # ← Already correct
  
  steps:
    - name: Deploy node
      env:
        SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
        EPHEMERAL_KEY: ${{ needs.automate-ssh-keys.outputs.ephemeral_key }}  # ← ADD THIS
        SSH_HOST: ${{ vars.SSH_HOST }}
        SSH_USER: ${{ vars.SSH_USER }}
      run: |
        # ... (rest of your existing script works as-is)
```

**Why this works:**
- The ephemeral key is passed through GitHub's internal job output mechanism
- It's automatically masked in logs (via `::add-mask::`)
- No manual copy/paste needed
- No storage in Secrets Manager required (it's ephemeral - regenerated each run)

### Option B: Use Permanent SSH Key in Secrets (Your Question)

**If you want to store a permanent key:**

1. **Generate a permanent SSH key locally:**
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/aequitas_deploy -N ""
   ```

2. **Copy the private key:**
   ```bash
   cat ~/.ssh/aequitas_deploy
   # Copy the output (starts with -----BEGIN OPENSSH PRIVATE KEY-----)
   ```

3. **Add to GitHub Secrets:**
   - Go to: `https://github.com/CreoDAMO/REPAR/settings/secrets/actions`
   - Click "New repository secret"
   - Name: `SSH_PRIVATE_KEY`
   - Value: Paste the entire private key (including BEGIN/END lines)
   - Click "Add secret"

4. **Copy the public key to your server:**
   ```bash
   cat ~/.ssh/aequitas_deploy.pub
   # Copy and add to authorized_keys on your deployment server
   
   ssh root@YOUR_SERVER_IP
   echo "YOUR_PUBLIC_KEY" >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

5. **Set SSH_HOST variable:**
   - Go to: `https://github.com/CreoDAMO/REPAR/settings/variables/actions`
   - Click "New repository variable"
   - Name: `SSH_HOST`
   - Value: Your server IP (e.g., `135.232.208.145`)
   - Click "Add variable"

**Then the workflow will use the permanent key as fallback:**
```bash
elif [ -n "$SSH_PRIVATE_KEY" ]; then
  echo "Using stored SSH_PRIVATE_KEY secret"
  mkdir -p ~/.ssh
  echo "$SSH_PRIVATE_KEY" > ~/.ssh/deploy_key
  chmod 600 ~/.ssh/deploy_key
```
