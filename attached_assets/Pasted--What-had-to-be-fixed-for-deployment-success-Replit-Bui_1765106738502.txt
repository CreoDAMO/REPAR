This is checking if the keplr-chain-registry directory exists, but it was created in a previous step ("Fork and clone Keplr registry"). The problem is that GitHub Actions runs each step in a fresh shell, and the previous step's working directory changes aren't preserved.
Looking at the workflow structure:
1. 
Step "Fork and clone Keplr registry" - clones the repo

2. 
Step "Create chain configuration" - creates the chain.json file

3. 
Step "Create PR" - tries to commit and push


The issue is that in step 2 ("Create chain configuration"), the workflow checks if [ ! -d keplr-chain-registry ] and then does cd keplr-chain-registry - but it's creating files in the keplr-chain-registry directory.
Then in step 3 ("Create PR"), it checks again if [ ! -d keplr-chain-registry ] but the directory should exist from step 1.
Wait, looking more carefully at the output:
- 
The "Create chain configuration" step shows it created the file at cosmos/aequitas.json

- 
But the output shows it was run from outside the keplr-chain-registry directory (it says "File: cosmos/aequitas.json" not "File: keplr-chain-registry/cosmos/aequitas.json")


The issue is that the workflow has a logic problem.
The "Fork and clone" step likely exited early if the GitHub token wasn't set, so the directory was never actually cloned. Even though the chain configuration step ran and created files, it must have created them in a temporary location or the wrong directory. When the PR step runs and checks for the cloned registry, it doesn't find it because the initial clone step failed silently.
The root cause is that GH_PAT isn't configured as a secret in the GitHub repository. Without it, the fork and clone operation skips entirely, leaving no directory for subsequent steps to work with. The workflow needs either the secret to be properly set up, or the logic should prevent later steps from running if the initial clone fails. The root cause is that step 1 exits early when GH_PAT is missing, so the repository never gets cloned. Step 3 then tries to check for the keplr-chain-registry directory that was never created, causing the PR creation to be skipped. The user needs to set up the GH_PAT secret in their repository settings for this workflow to function properly.
